QR Scanning at the Terminal

The terminal scanning module allows authorized staff to verify registered drivers and process authorized terminal transactions using a designated hardware QR scanner connected to the terminal workstation.

QR Scanning Module Drivers · Staff · Cashiers · Administrators

The QR scanning module is the terminal-side counterpart of the driver's QR code. Authorized staff scan the driver's QR code using the designated hardware scanner, and the system retrieves the corresponding driver record to verify identity, check account status, validate the applicable transaction, and record the completed activity in the centralized transaction database.

01

Terminal Process

1
Scanner Ready

The designated hardware QR scanner is connected to the terminal workstation and prepared to receive QR information.

2
Driver Presents QR Code

The driver presents the QR code associated with their Driver ID.

3
Scan QR Code

The authorized staff member scans the driver's QR code using the designated hardware scanner.

4
QR Verification

The system processes the scanned QR information and searches for the corresponding driver record.

5
Driver Information Display

Once recognized, the system displays the information authorized for staff verification.

6
Account Status Check

The system checks the driver's account status before allowing the applicable transaction to continue.

7
Transaction Validation

For transactions requiring prepaid balance, the system checks the driver's available balance and the applicable terminal fee.

8
Sufficient Balance

If the balance is sufficient, the applicable terminal fee is deducted and the remaining balance is calculated.

9
Insufficient Balance

If the balance is insufficient, the transaction is not completed automatically and the driver may load additional balance through the cashier.

10
Transaction Confirmation

The system displays a transaction confirmation with the recorded details.

11
Reference or Receipt Information

Where applicable, the system records the authorized payment or receipt reference associated with the transaction.

12
Transaction Record Saved

Once completed, the system saves the activity in the centralized transaction database.

Hardware Scanner Note

The terminal scanning process is designed around the designated hardware scanner rather than requiring staff to use a personal cellphone camera.

02

QR Verification Checks

The system processes the scanned QR information and searches for the corresponding driver record. The system checks whether:

  • The QR code exists
  • The driver record is registered
  • The account is active
  • The QR code corresponds to the registered driver

Once recognized, the system displays the information authorized for staff verification, which may include:

  • Driver ID
  • Driver name
  • Vehicle type
  • Plate number
  • Account status

Staff should verify that the displayed information matches the driver presenting the QR code.

03

Account Status Results

Possible results include:

Active

The driver may proceed with the applicable transaction.

Pending

The account requires the appropriate verification or approval.

Inactive

The applicable transaction cannot proceed.

Invalid QR

The scanned QR code cannot be matched to a valid system record.

The exact account-status rules should follow the procedures configured by the responsible office.

04

Balance and Transaction Validation

Sufficient Balance

If the available prepaid balance is sufficient:

  • The system confirms the available balance.
  • The applicable terminal fee is determined.
  • The authorized amount is deducted.
  • The remaining balance is calculated.
  • The transaction is recorded.

Insufficient Balance

If the driver's balance is insufficient:

  • The system identifies the insufficient balance.
  • The transaction should not be completed automatically.
  • The staff informs the driver of the available balance.
  • The driver may proceed to the designated cashier process to load an authorized prepaid amount.
  • The transaction can be processed according to the applicable terminal procedure after the balance requirement is satisfied.
05

Transaction Confirmation

After successful processing, the system displays a transaction confirmation. The confirmation may include:

  • Transaction ID
  • Driver ID
  • Driver name
  • Vehicle type
  • Plate number
  • Applicable fee
  • Amount deducted
  • Remaining balance
  • Date and time
  • Staff account
  • Transaction status

Where applicable, the system records the authorized payment or receipt reference associated with the transaction. The reference information may be linked to the appropriate driver and transaction record.

Important

The system should only be described as issuing an official government receipt if the responsible office has formally authorized that function.

06

When the QR Code Cannot Be Scanned

If the scanner cannot read the QR code, staff should first check:

  • Whether the QR code is clearly presented
  • Whether the hardware scanner is connected
  • Whether the scanner is functioning correctly
  • Whether the system is ready to receive the scan

The staff should not manually create a transaction using an unverified driver record unless an authorized alternative procedure exists.

07

When the QR Code Is Invalid

If the system cannot find a matching driver record, the system should display an appropriate notification such as:

QR Code Not Recognized

The transaction should not proceed automatically. Staff should follow the applicable terminal verification procedure or refer the driver to the responsible personnel for assistance.

08

Staff Responsibilities

Authorized staff operating the scanning module should:

  • Use the designated hardware scanner
  • Verify the driver's information
  • Confirm the account status
  • Check the applicable transaction requirements
  • Verify sufficient prepaid balance when required
  • Confirm the transaction before completion
  • Ensure the correct driver is associated with the transaction
  • Review the transaction confirmation
  • Report system or scanner problems
  • Protect driver information from unauthorized access
09

Transaction Workflow

The complete terminal scanning workflow is:

Driver Presents QR
Hardware Scanner Reads QR
System Finds Driver Record
Driver Information Displayed
Account Status Verified
Transaction Validated
Prepaid Balance Checked
Applicable Fee Deducted
Transaction Confirmed
Reference / Receipt Recorded
Transaction Saved
Available in Records and Reports
10

Security and Access Control

The QR scanning module is restricted to authorized staff accounts.

Staff should only access information necessary to perform their assigned terminal responsibilities. The system should prevent unauthorized users from accessing restricted driver and transaction information.

QR scanning is intended for driver identification and authorized terminal transaction processing. It does not by itself establish the driver's legal authorization to operate a public utility vehicle.

11

Result

A successful QR scanning transaction provides a faster and more organized method for identifying registered drivers and recording authorized terminal activity.

The completed transaction becomes part of the driver's transaction history and the terminal's centralized records for authorized monitoring, reporting, and administrative review.

—

Important System Boundary

System Scope

The system records authorized payment and reference information and manages prepaid balances and terminal transactions.

It should not be represented as an official government payment processor or official government receipt issuer unless those functions have been formally authorized by the responsible office.

Actual terminal procedures, fee schedules, receipt requirements, and transaction rules remain subject to the applicable requirements of the responsible office.
