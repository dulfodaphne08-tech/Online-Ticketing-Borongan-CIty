Intellectual Property Rights Policy

Guidelines for the ownership, permitted use, attribution, and protection of materials associated with the QR-Based Transport Ticketing and Fee Collection System.

Policy Document Project Team · Adviser · Institution

This policy explains how intellectual property and project materials associated with the Borongan City Transport Terminal QR-Based Transport Ticketing and Fee Collection System should be handled. It covers the system's source code, interface design, database structure, documentation, original project content, images, multimedia, and third-party resources used as part of the academic project.

01

Ownership of the Platform

The QR-Based Transport Ticketing and Fee Collection System is an academic project developed by the project team.

Project materials may include:

  • System interface and visual design
  • Source code
  • Database structure
  • System workflows
  • System documentation
  • Original project content
  • Project-created graphics and materials

Ownership and permitted use of these materials are subject to applicable school, institutional, project, and adviser requirements.

The system name, project design, interface, documentation, and other original project materials should not be represented as another person's or organization's original work.

02

Source Code and System Design

The project may contain source code, database structures, system architecture, user interfaces, workflows, and other technical components developed by the project team.

These materials are intended for legitimate:

  • Academic purposes
  • System development
  • Maintenance
  • Testing
  • Demonstration
  • Project evaluation

Project materials should not be copied, redistributed, modified, or presented as another person's original work without appropriate authorization.

03

Original Project Content

Content created specifically for the system should be original or properly authorized.

This may include:

  • System descriptions
  • Page content
  • User instructions
  • System documentation
  • Workflow descriptions
  • Graphics
  • Project-created illustrations
  • Other original materials

Project members should not copy another person's work and present it as their own. Where external content is required, the project team should follow the applicable permission, licensing, and attribution requirements.

04

Images and Multimedia

Images, videos, photographs, logos, icons, illustrations, and other multimedia materials obtained from third parties should only be used when appropriate permission, authorization, or licensing allows their use.

Where attribution is required, the source or creator should be properly acknowledged.

The use of third-party material does not transfer ownership of that material to the project team.

05

Third-Party Materials

The system may contain materials created or owned by individuals, organizations, government offices, software developers, or other third parties.

Examples may include:

  • Photographs
  • Videos
  • Logos and seals
  • Icons
  • Illustrations
  • Fonts
  • Software libraries
  • Frameworks
  • Open-source software
  • External documentation

Third-party materials remain subject to the rights, permissions, and licenses of their respective owners. The project team should comply with the applicable conditions for each material used.

06

Open-Source Software and Libraries

The system may use third-party libraries, frameworks, fonts, icons, or other open-source resources.

These resources remain subject to their respective licenses.

The project team should review and comply with applicable license requirements when using, modifying, or redistributing open-source resources.

Use of an open-source component does not mean that the project team owns the original component.

07

Database and System Records

The database structure and system configuration developed as part of the project are considered project materials.

However, records entered into the system may contain information concerning registered drivers, cashiers, staff, administrators, and other authorized users.

Examples may include:

  • Driver information
  • Vehicle information
  • Account information
  • Prepaid balance records
  • Transaction records
  • Payment or reference information
  • Staff or cashier records

Information contained in the system should be handled according to the applicable Data Privacy Policy, security procedures, assigned user roles, and authorized system purposes.

This Intellectual Property Rights Policy does not grant the project team ownership of personal information.

This policy does not claim ownership of third-party materials, software, images, logos, videos, fonts, libraries, or other content referenced or incorporated into the system. — Policy Scope
08

User-Submitted Information

Information submitted by registered drivers or authorized personnel should be handled according to the system's applicable privacy and security requirements.

Submitting information to the system does not automatically transfer ownership of personal information or other materials belonging to the user.

Information should only be accessed, processed, or used for legitimate system, administrative, academic, or operational purposes authorized by the responsible office.

09

Modification and Redistribution

The system and its original project materials should not be:

  • Copied and presented as another person's work
  • Redistributed without appropriate authorization
  • Reused as another project without proper permission
  • Modified and submitted as an unrelated original project
  • Published or commercially distributed without the required authorization

Academic, institutional, licensing, and project requirements should always be followed.

10

Attribution

When external materials are used, appropriate attribution should be provided when required by the applicable license, permission, or usage conditions.

Attribution may identify:

  • Creator or author
  • Source
  • Applicable license
  • Relevant usage information

Attribution should be placed in an appropriate location within the website, documentation, or project materials.

11

Protection of Project Work

Project members and authorized personnel should take reasonable steps to protect project resources from unauthorized access or misuse.

This may include:

  • Source code
  • Database structure
  • Project documentation
  • System design files
  • Development files
  • Account credentials
  • Private configuration information

System credentials, passwords, API keys, database keys, and other private configuration information should not be publicly disclosed.

12

Reporting Intellectual Property Concerns

If a project member, contributor, or authorized person believes that copyrighted or otherwise protected material has been used improperly within the system, the concern should be reported to the responsible project team, project adviser, or appropriate institutional office.

A report should identify:

  • The material involved
  • Where the material appears
  • The suspected source or owner, when known
  • The reason for the concern
  • Any available supporting information

The project team should review reported concerns and take appropriate action based on applicable project, institutional, licensing, and legal requirements.

13

Questions and Inquiries

Questions concerning:

  • Project ownership
  • Permitted use
  • Attribution
  • Source materials
  • Third-party content
  • Open-source licenses
  • Intellectual property concerns

should be directed to the responsible project team, project adviser, or appropriate institutional office.

—

Important Notice

Policy Scope

This policy describes the intended handling of intellectual property within the Borongan City Transport Terminal QR-Based Transport Ticketing and Fee Collection System academic project.

It does not claim ownership of third-party materials, software, images, logos, videos, fonts, libraries, or other content that may be referenced or incorporated into the system.

Ownership, licensing, attribution, and usage rights remain subject to the applicable agreements, licenses, institutional policies, permissions, and applicable law.

This policy is intended to provide general project guidelines and should not be interpreted as a legal determination of ownership or intellectual property rights.
