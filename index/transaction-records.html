Digital Transaction Records

The system maintains centralized digital records of authorized terminal transactions to support accurate monitoring, searching, verification, and reporting. Digital transaction records provide a consistent history of activities performed through the QR-Based Transport Ticketing and Fee Collection System.

Transaction Records Module Drivers · Cashiers · Staff · Administrators

The Digital Transaction Records module stores a centralized history of authorized terminal activity — connecting driver identification, vehicle information, applicable fees, prepaid balance deductions, staff and cashier accounts, and transaction status into one consistent record for monitoring, searching, verification, and reporting.

02

Transaction Recording Process

1
Driver Identification

The driver's QR code is scanned using the designated terminal scanner.

2
Driver Verification

The system retrieves the registered driver and vehicle information associated with the QR code.

3
Transaction Validation

The system checks the driver's account status and, when required, verifies whether sufficient prepaid balance is available.

4
Fee Application

The system determines the applicable terminal fee based on the configured vehicle type and authorized fee schedule.

5
Balance Deduction

When applicable, the authorized terminal fee is deducted from the driver's available prepaid balance.

6
Transaction Creation

The system creates a transaction record containing the relevant driver, vehicle, fee, balance, staff, and time information.

7
Transaction Confirmation

The completed transaction is assigned a transaction status and becomes part of the driver's transaction history and centralized terminal records.

03

Transaction Status

The system may use transaction statuses to help authorized personnel identify the current condition of each transaction. Examples include:

Completed

Transaction was successfully processed.

Pending

Transaction requires additional processing or verification.

Failed

Transaction could not be completed.

Cancelled

Transaction was cancelled through an authorized procedure.

Insufficient Balance

Available prepaid balance was not enough to complete the transaction.

The exact statuses may be configured according to the approved procedures of the responsible terminal office.

04

Transaction History

Authorized users can search and review transaction records using available filters such as:

  • Transaction ID
  • Driver ID
  • Driver name
  • Plate number
  • Vehicle type
  • Date
  • Transaction status
  • Staff
  • Cashier
  • Payment/reference information, when applicable

This allows authorized personnel to locate specific transactions without manually reviewing all records.

05

Driver Transaction History

Drivers may be provided access to the transaction information authorized for their account.

This may include:

  • Transaction date
  • Transaction time
  • Applicable fee
  • Amount deducted
  • Remaining balance
  • Transaction status
  • Transaction reference, when applicable

Drivers should only be able to view information associated with their own authorized account.

06

Cashier Transaction Records

Cashier-related records may include:

  • Driver account
  • Load amount
  • Date and time of loading
  • Payment/reference information
  • Cashier account responsible for the transaction
  • Updated prepaid balance
  • Transaction status

These records help connect prepaid balance loading with the appropriate driver's account.

07

Staff Transaction Records

Staff-related transaction records may include:

  • Staff account
  • Driver ID
  • Driver name
  • Vehicle information
  • Transaction date and time
  • Applicable fee
  • Amount deducted
  • Transaction status

This allows authorized administrators to determine which staff account processed a particular terminal transaction.

08

Record Verification

Before completing a transaction, authorized personnel should verify the displayed information, including:

1
Driver Identity

Confirm the displayed driver information matches the person presenting the QR code.

2
Vehicle Information

Verify the registered vehicle type and plate number.

3
Account Status

Confirm the account is active and eligible for the transaction.

4
Applicable Fee

Confirm the fee corresponds to the configured vehicle type.

5
Available Prepaid Balance

Confirm sufficient balance is available when required.

6
Transaction Details

Review the transaction details before completing.

This helps reduce incorrect transactions and prevents information from being recorded under the wrong driver account.

09

Record Correction

If incorrect information is discovered, authorized administrators may correct the appropriate driver or transaction information according to the system's administrative procedures.

Where audit logging is implemented, important changes should record:

  • Account that performed the change
  • Date and time of the change
  • Record affected
  • Type of modification

Original transaction records should not be casually deleted or altered because transaction history is important for monitoring and accountability.

10

Transaction Search and Filtering

Authorized personnel may use search and filtering tools to locate records more efficiently.

By Driver

Driver ID, driver name

By Vehicle

Vehicle type, plate number

By Date

Specific date, date range

By Transaction

Transaction ID, transaction status, transaction type

By Personnel

Cashier, staff

These filters support faster review of large numbers of transaction records.

11

Records for Reports

Recorded transactions serve as the source of information for authorized reports and monitoring functions.

The system may use transaction records to generate:

  • Daily terminal reports
  • Monthly transaction reports
  • Vehicle-type reports
  • Driver transaction reports
  • Cashier reports
  • Staff transaction reports
  • Other authorized operational reports

Only authorized users should have access to reports containing restricted or personal information.

12

Audit and Accountability

Important system activities should be traceable where audit logging is implemented.

Audit information may include:

  • User account
  • User role
  • Date and time
  • Action performed
  • Affected record
  • Previous value, when applicable
  • Updated value, when applicable

This provides greater accountability and helps administrators determine who performed an authorized action and when it occurred.

13

Data Protection

Transaction records may contain personal and operational information. Access should therefore be restricted according to the user's assigned system role.

Drivers should only access information authorized for their own account, while Cashiers, Staff, and Administrators should only access records necessary for their assigned responsibilities.

14

Purpose of Digital Transaction Records

Digital transaction records help:

Reduce manual recordkeeping
Minimize recording errors
Make transactions easier to trace
Provide faster record searching
Maintain driver transaction history
Support prepaid balance monitoring
Support cashier and staff accountability
Provide information for authorized reports
Improve administrative monitoring
Maintain centralized transaction information
—

Important System Boundary

System Scope

The system records authorized terminal transactions and payment/reference information based on the configured procedures.

It should not be represented as an official government payment processor or official government receipt issuer unless the responsible terminal office has formally authorized those functions.
